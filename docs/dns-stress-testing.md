# DNS压力测试：放大方法与防护验证

DNS是基础设施里最容易被忽视的测试面。它同时具备两个风险特征：单点故障（域名解析挂了等于全站挂）和放大效应（小查询撬动大响应）。这份指南拆解DNS压力测试的方法选择与评估要点。

## 为什么DNS值得单独测

1. **放大效应**：DNS响应远大于请求。ANY查询对某些记录类型的放大倍率可达20-50倍，EDNS0更大。100Mbps的查询流量经过放大后，对目标造成的冲击是数Gbps级。
2. **链路依赖**：CDN、负载均衡、服务发现全依赖DNS。解析层降级时，上层防护还没被打穿，业务已经不可用。
3. **缓存掩盖问题**：平时TTL缓存掩盖了权威服务器的真实容量，出事时才知道解析层多脆弱。

## 测试面拆解

### 递归解析器（自建或运营商）

| 测试项 | 验证什么 |
|--------|---------|
| 缓存命中率 | 热点域名查询是否命中本地缓存 |
| 未命中回源压力 | cache miss时回源链路是否成为瓶颈 |
| NXDOMAIN洪泛 | 大量不存在域名的查询把缓存和回源同时打满 |
| CHAOS/ANY查询 | 老旧软件对畸形查询的健壮性 |

### 权威服务器

| 测试项 | 认证服务器特有 |
|--------|---------------|
| 正常域名+随机子域 | 随机子域绕过缓存直接压权威（NXDOMAIN路径） |
| 文本记录大响应 | TXT记录构造大响应，验证UDP分片处理 |
| TCP回退 | UDP截断后的TCP重试是否拖垮连接池 |
| 区域传送请求 | AXFR滥用是否被限制 |

## 方法选择

- **随机子域查询**（random subdomain）：绕过一切缓存的利器。`a8f3.example.com`、`b7d2.example.com`……每一个都是cache miss，全部落到权威服务器。这是压测权威容量的标准手法。
- **NXDOMAIN洪泛**：只查不存在的域名。递归解析器需要对每个NXDOMAIN做完整回源链路，CPU消耗远高于缓存命中。
- **放大反射测试**：用自己的解析器做反射源验证防护。注意——反射测试只应针对自有资产，且需在约定窗口内进行。

## 评估指标

- **QPS容量拐点**：正常域名解析延迟从基线到劣化50%的QPS阈值
- **NXDOMAIN比例阈值**：NXDOMAIN占比多少时解析延迟开始失控
- **UDP分片丢弃率**：大响应触发分片后，中间网络设备的丢弃行为
- **恢复时间**：停止测试后缓存命中率恢复到基线的时间

## 常见坑

1. **只测热点域名**：全命中缓存，测了个寂寞。必须用随机子域绕缓存。
2. **忘了TCP回退**：UDP响应被截断后客户端走TCP重试，53端口的TCP连接池是常见隐藏瓶颈。
53端口的TCP没测，等于DNS测试只做了一半。
3. **TTL陷阱**：测试前刚刷新过TTL，缓存全热，结果严重失真。
