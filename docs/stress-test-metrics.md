# 压力测试指标解读：Gbps、PPS、RPS

## 三个维度看压力

很多人只盯Gbps一个数字，这是最大的误区。压力测试有三个互相独立的指标维度：

### 带宽（Gbps）

单位时间传输的数据量。决定因素：出口带宽、清洗中心牵引能力。

### 包速率（PPS，Packets Per Second）

每秒发送的数据包数量。同样1Gbps，64字节小包约190万PPS，1500字节大包只有约8.3万PPS——差23倍。

设备处理的是"包"而不是"字节"。防火墙、路由器的转发能力以PPS为硬指标，中端设备往往在数百万PPS就达到极限，此时带宽可能才跑了几百Mbps。

### 请求速率（RPS，Requests Per Second）

L7专用指标：每秒完成的HTTP(S)请求数。决定Web服务器、PHP-FPM、数据库的实际承载极限。

## 换算速查

```
PPS ≈ Gbps × 125,000,000 / 平均包大小(字节)

例：1Gbps ÷ 64字节 ≈ 195万 PPS
    1Gbps ÷ 1400字节 ≈ 8.9万 PPS
```

## 瓶颈定位对照

| 症状 | 瓶颈位置 |
|------|---------|
| 带宽打满，服务正常 | 入口带宽，上CDN/清洗 |
| PPS高但带宽低，设备CPU飙高 | 防火墙/路由器转发极限 |
| RPS高，响应时间陡增 | 应用层（连接池/数据库/渲染） |
| TLS握手失败率上升 | TLS计算资源（上硬件加速） |

## 测试报告应该记录什么

- 各指标峰值与持续值（峰值能扛≠持续能扛）
- 目标端响应延迟变化曲线
- 丢包率开始抬升的拐点
- 测试方法的包大小分布
